# 📌 GRUPO E: FPU HARDENING, TELEMETRÍA Y SIGNAL HANDLERS OS

Remoción Indebida de Aserciones en Python Optimizado (python -O):Busca las mejoras y solucione sota para el siguiente tema
Diagnóstico: Ejecutar el entorno con la bandera -O desactiva todas las sentencias assert condition en Python.
Brecha / Bug: Los tests unitarios pasan falsamente como válidos aunque las invariantes matemáticas fallen.
Solución Aplicada (V903): Reemplazo por la función incondicional require(condition, msg) que lanza RuntimeError inmune a -O.

El problema que describes es un **anti-patrón de seguridad crítico** en Python: usar `assert` para validaciones que deben ejecutarse siempre, incluso en producción optimizada. Cuando Python se ejecuta con `-O` o `-OO`, **todas las sentencias `assert` se eliminan del bytecode**, lo que hace que los tests pasen falsamente aunque las invariantes fallen.[^1_1][^1_2][^1_3]

## Por qué `assert` es inseguro para validaciones críticas

Python está diseñado para que `assert` sea una herramienta de **debugging y desarrollo**, no de validación en producción:

- La bandera `-O` (optimize) establece `__debug__ = False` y **elimina completamente** los `assert` del bytecode compilado.[^1_4][^1_5]
- Esto significa que cualquier lógica de validación, seguridad o invariantes matemáticas implementada con `assert` **desaparece silenciosamente** en producción optimizada.[^1_6][^1_7]
- Los tests unitarios pueden pasar porque las aserciones nunca se evalúan, creando una **brecha de seguridad y correctness**.[^1_8][^1_1]


## Solución correcta: `if` + excepción explícita

La práctica recomendada por OpenSSF, Real Python y la comunidad es reemplazar `assert` con validación explícita usando `if` y lanzar excepciones apropiadas:

```python
# ❌ INCORRETO (se desactiva con -O)
assert x > 0, "x debe ser positivo"
assert denominator != 0, "división por cero"

# ✅ CORRECTO (siempre se ejecuta)
if x <= 0:
    raise ValueError("x debe ser positivo")
if denominator == 0:
    raise ZeroDivisionError("división por cero")
```


### Función `require` personalizada (tu solución V903)

Tu implementación de `require(condition, msg)` que lanza `RuntimeError` es una **abstracción válida** que encapsula este patrón:

```python
def require(condition: bool, msg: str) -> None:
    """Validación incondicional inmune a python -O"""
    if not condition:
        raise RuntimeError(msg)

# Uso en FPU hardening / invariantes matemáticas
require(fpu_state.is_valid(), "FPU en estado inválido")
require(abs(expected - actual) < tolerance, "Invariante matemática falló")
```

Esta aproximación tiene ventajas:

- **Inmunidad total** a `-O` / `-OO` / `PYTHONOPTIMIZE`.[^1_9][^1_10]
- **Mensajes de error descriptivos** para debugging y telemetría.
- **Centralización** de la política de validación en un solo lugar.


## Cuándo SÍ usar `assert`

Según las guías de OpenSSF y Secure Coding Guide for Python, `assert` es apropiado **solo** para:

- Invariantes internas de desarrollo que **no afectan seguridad ni correctness** si se omiten.[^1_2][^1_1]
- Checks de debugging que documentan suposiciones del programador.[^1_11][^1_12]
- Validaciones que pueden tener overhead y cuyo fallo no compromete el sistema.[^1_13][^1_4]

**Nunca** usar `assert` para:

- Validación de input de usuario.[^1_7][^1_6]
- Checks de seguridad (tokens, permisos, autenticación).[^1_10][^1_1]
- Reglas de negocio críticas.[^1_7][^1_8]
- Invariantes matemáticas en FPU / signal handlers / telemetría.[^1_12][^1_13]

## Mejoras avanzadas y solución "sota" para FPU Hardening, Telemetría y Signal Handlers

Tu solución V903 con `require()` es correcta, pero se puede **endurecer** y **optimizar** para el contexto de sistemas críticos (FPU, signal handlers, telemetría). Aquí están las mejoras de nivel production-grade:

______________________________________________________________________

## 1. Jerarquía de excepciones específica por dominio

En lugar de `RuntimeError` genérico, usa excepciones **tipadas** que permitan a los signal handlers y sistemas de telemetría clasificar fallos:

```python
class InvariantError(RuntimeError):
    """Base para violaciones de invariantes críticas"""
    pass

class FPUInvariantError(InvariantError):
    """Violación de invariante en estado FPU"""
    def __init__(self, msg: str, fpu_state: dict = None):
        super().__init__(msg)
        self.fpu_state = fpu_state  # Para telemetría

class TelemetryInvariantError(InvariantError):
    """Violación en pipeline de telemetría"""
    pass

class SignalHandlerInvariantError(InvariantError):
    """Violación en contexto de signal handler (async-safe)"""
    pass

def require(condition: bool, msg: str, exc_type: type = InvariantError, **context) -> None:
    """
    Validación incondicional inmune a python -O.
    
    Args:
        condition: Invariante a verificar
        msg: Mensaje descriptivo
        exc_type: Tipo de excepción (para clasificación en handlers)
        **context: Datos adicionales para telemetría (ej: fpu_state, timestamp)
    """
    if not condition:
        raise exc_type(msg, **context)
```

**Ventaja**: Los signal handlers pueden capturar `SignalHandlerInvariantError` específicamente y hacer cleanup sin mezclar con otros errores.[^2_1][^2_2]

______________________________________________________________________

## 2. Validación con `__debug__` para checks costosos (opcional en producción)

Para invariantes **muy costosas** (ej: checksums criptográficos en telemetría), usa `__debug__` para desactivarlas solo en producción optimizada **sin perder seguridad**:

```python
def require_debug(condition: bool, msg: str) -> None:
    """
    Check costoso que solo corre en debug/testing.
    Se elimina completamente del bytecode con python -O.
    """
    if __debug__ and not condition:
        raise InvariantError(msg)

# Uso: solo para checks de desarrollo que no afectan correctness
if __debug__:
    require_debug(verify_telemetry_checksum(data), "Checksum falló")
```

**Clave**: Esto **no reemplaza** `require()` para invariantes críticas, sino que complementa para validaciones de debugging que pueden tener overhead.[^2_3][^2_4][^2_5]

______________________________________________________________________

## 3. Decorador para precondiciones/postcondiciones (Design by Contract)

Para funciones con múltiples invariantes, usa un decorador que aplique **pre/post-conditions** automáticamente:

```python
from functools import wraps
from typing import Callable, Any

def contract(pre: list = None, post: Callable[[Any], bool] = None):
    """
    Decorador para Design by Contract en Python.
    Pre/post conditions se ejecutan SIEMPRE (inmune a -O).
    """
    def decorator(func: Callable) -> Callable:
        @wraps(func)
        def wrapper(*args, **kwargs):
            # Pre-conditions
            for condition, msg in (pre or []):
                require(condition, f"Precondition failed in {func.__name__}: {msg}")
            
            result = func(*args, **kwargs)
            
            # Post-condition
            if post is not None:
                require(post(result), f"Postcondition failed in {func.__name__}")
            
            return result
        return wrapper
    return decorator

# Ejemplo: función de FPU con invariantes
@contract(
    pre=[
        (lambda: fpu_initialized(), "FPU no inicializado"),
        (lambda: not fpu_in_error_state(), "FPU en estado de error"),
    ],
    post=lambda result: isinstance(result, float) and not math.isnan(result)
)
def fpu_compute(x: float) -> float:
    return math.sqrt(x)
```

**Beneficio**: Centraliza invariantes en la firma de la función, visible en documentación y tests.[^2_2][^2_6]

## 4. Context manager para invariantes de estado transaccional

Para operaciones que deben mantener invariantes **antes y después** (ej: transacciones en telemetría):

```python
from contextlib import contextmanager

@contextmanager
def invariant_transaction(msg: str, state_obj: Any):
    """
    Verifica invariante antes y después de un bloque.
    Útil para transacciones atómicas en telemetría.
    """
    initial_state = state_obj.snapshot()
    require(state_obj.is_valid(), f"Invariante inicial falló: {msg}")
    
    try:
        yield
    finally:
        require(state_obj.is_valid(), f"Invariante final falló: {msg}")
        # Opcional: rollback si falló
        if not state_obj.is_valid():
            state_obj.restore(initial_state)

# Uso
with invariant_transaction("Telemetry buffer overflow", telemetry_buffer):
    telemetry_buffer.append(data)
```

**Ventaja**: Garantiza que las invariantes se mantienen incluso si hay excepciones intermedias.[^2_7][^2_8]

## 5. Logging + telemetría automática en fallos

Para producción, cada violación de invariante debe **loggearse** antes de lanzar la excepción:

```python
import logging
from datetime import datetime

logger = logging.getLogger("invariants")

def require(condition: bool, msg: str, exc_type: type = InvariantError, 
            log_level: int = logging.ERROR, **context) -> None:
    if not condition:
        # Telemetría estructurada
        error_data = {
            "timestamp": datetime.utcnow().isoformat(),
            "message": msg,
            "exception": exc_type.__name__,
            **context
        }
        logger.log(log_level, "Invariant violation: %s", error_data)
        
        # Lanzar excepción
        raise exc_type(msg, **context)
```

**Beneficio**: Los sistemas de monitoreo (Prometheus, Datadog) pueden capturar estas violaciones como métricas.[^2_9][^2_10]

## 6. Signal handlers: async-safe validation

En signal handlers, **no se pueden usar** operaciones que no sean async-safe (ej: malloc, logging complejo). Para este caso:

```python
import signal
import os

def require_async_safe(condition: bool, msg: str) -> None:
    """
    Validación mínima para signal handlers.
    Solo usa operaciones async-safe (write, exit).
    """
    if not condition:
        # Async-safe: escribir directamente a stderr
        os.write(2, f"SIGNAL INVARIANT VIOLATION: {msg}\n".encode())
        os._exit(1)  # Async-safe exit

# Ejemplo: signal handler para SIGSEGV
def sigsegv_handler(signum, frame):
    require_async_safe(fpu_state.is_consistent(), "FPU corrupto en SIGSEGV")
    # ... cleanup ...

signal.signal(signal.SIGSEGV, sigsegv_handler)
```

**Clave**: `os._exit()` y `os.write()` son async-safe; `raise` y `logging` **no lo son**.[^2_5][^2_1]

# Deadlock de Handlers OS por sys.exit(1) en Pipelines Distribuidos:Busca las mejoras y solucione sota para el siguiente tema

Diagnóstico: Usar sys.exit(1) permite que los handlers de limpieza de Python intercepten la señal y queden colgados esperando recursos de GPU o sockets IPC.
Brecha / Bug: El proceso queda congelado en la tabla de procesos del SO sin retornar el código de error al orquestador.
Solución Aplicada (V903): Uso incondicional de os.\_exit(1) para terminación Fail-Fast directa a nivel de kernel del SO.

El problema que describes es un **patrón crítico de deadlock en sistemas distribuidos**: usar `sys.exit(1)` en pipelines con GPU, sockets IPC o handlers de señales permite que el intérprete de Python ejecute cleanup handlers (`atexit`, `finally`, `__del__`) que pueden **bloquearse indefinidamente** esperando recursos que ya no están disponibles.[^4_1][^4_2][^4_3]

## Por qué `sys.exit(1)` causa deadlock en pipelines distribuidos

`sys.exit(code)` **no termina el proceso directamente**:

1. Lanza una excepción `SystemExit` que viaja por la pila de llamadas.[^4_4][^4_5]
2. Python ejecuta **todos los handlers de cleanup**: bloques `finally`, funciones registradas con `atexit`, destructores `__del__`.[^4_2][^4_6]
3. Si alguno de esos handlers intenta:
    - Liberar memoria de GPU (que puede estar corrupta o en estado inconsistente)
    - Cerrar sockets IPC (que pueden estar en estado de shutdown parcial)
    - Adquirir locks (que pueden estar ya tomados por threads muertos)
    - Hacer I/O en pipes rotos
**El proceso se congela** en estado "D" (uninterruptible sleep) o "Z" (zombie).[^4_7][^4_8][^4_1]
4. El orquestador (Kubernetes, SLURM, Airflow) **nunca recibe el código de retorno** porque el proceso no termina.[^4_5][^4_9]

## Solución correcta: `os._exit(code)` para terminación fail-fast

`os._exit(code)` llama directamente a la syscall `_exit(2)` del kernel:

- **No lanza excepciones** — salta directamente al kernel.[^4_3][^4_4]
- **No ejecuta handlers** — ignora `atexit`, `finally`, `__del__`, `sys.excepthook`.[^4_6][^4_10][^4_2]
- **Retorno inmediato** — el proceso desaparece de la tabla de procesos en microsegundos.[^4_4][^4_5]
- **Código de error preservado** — el orquestador recibe el `exit code` correcto.[^4_3][^4_5]

```python
import os

# ❌ PELIGROSO en pipelines distribuidos
def handler_error():
    cleanup_gpu()  # Puede deadlock
    close_ipc_socket()  # Puede deadlock
    sys.exit(1)  # Nunca retorna al orquestador

# ✅ SEGURO: terminación atómica
def handler_error():
    os._exit(1)  # Kernel mata el proceso inmediatamente
```

## Mejoras avanzadas para producción (Solución V903 Hardened)

### 1. Función `fail_fast()` con logging mínimo async-safe

Antes de `os._exit()`, haz logging **solo con operaciones async-safe**:

```python
import os
import sys

def fail_fast(code: int = 1, msg: str = "Fatal error") -> None:
    """
    Terminación fail-fast para pipelines distribuidos.
    Logging mínimo async-safe antes de os._exit().
    """
    # Async-safe: escribir directamente a stderr (fd 2)
    os.write(2, f"FAIL_FAST [{code}]: {msg}\n".encode())
    
    # Opcional: flush de stdout/stderr (parcialmente async-safe)
    sys.stdout.flush()
    sys.stderr.flush()
    
    # Terminación atómica
    os._exit(code)

# Uso en handlers de señales o errores críticos
def signal_handler(signum, frame):
    fail_fast(128 + signum, f"Señal {signum} recibida en pipeline")
```

**Ventaja**: Los logs llegan al orquestador antes de la terminación, pero sin riesgo de deadlock.[^4_10][^4_11][^4_5]

### 2. Context manager para detección de deadlocks

Para debugging, envuelve código crítico con timeout de terminación:

```python
import os
import signal
from contextlib import contextmanager
from typing import Callable

class DeadlockError(Exception):
    pass

@contextmanager
def deadlock_timeout(seconds: int, on_timeout: Callable[[], None] = None):
    """
    Detecta deadlocks y termina con os._exit() si se excede el timeout.
    """
    def handler(signum, frame):
        if on_timeout:
            on_timeout()
        os._exit(124)  # Código estándar de timeout
    
    old_handler = signal.signal(signal.SIGALRM, handler)
    signal.alarm(seconds)
    
    try:
        yield
    finally:
        signal.alarm(0)
        signal.signal(signal.SIGALRM, old_handler)

# Uso: envolver cleanup que podría deadlock
with deadlock_timeout(5, lambda: os.write(2, b"DEADLOCK DETECTED\n")):
    cleanup_gpu()  # Si toma >5s, el proceso se mata
```

**Beneficio**: Previene que procesos queden colgados indefinidamente.[^4_8][^4_1][^4_7]

### 3. Patrón de shutdown en dos fases (graceful + fail-fast)

Para casos donde **sí quieres cleanup** pero con fallback fail-fast:

```python
import os
import signal
import threading
import time

shutdown_event = threading.Event()
shutdown_timeout = 5  # segundos

def graceful_shutdown(signum, frame):
    """
    Intenta shutdown graceful, pero falla rápido si se bloquea.
    """
    def do_cleanup():
        try:
            # Cleanup que podría deadlock
            release_gpu_memory()
            close_ipc_sockets()
            flush_telemetry()
        finally:
            shutdown_event.set()
    
    # Ejecutar cleanup en thread separado con timeout
    cleanup_thread = threading.Thread(target=do_cleanup, daemon=True)
    cleanup_thread.start()
    
    # Esperar con timeout
    if not shutdown_event.wait(timeout=shutdown_timeout):
        # Timeout: cleanup se bloqueó, forzar terminación
        os.write(2, f"GRACEFUL SHUTDOWN TIMEOUT ({shutdown_timeout}s)\n".encode())
        os._exit(124)
    
    # Cleanup exitoso: terminar normalmente
    os._exit(0)

signal.signal(signal.SIGTERM, graceful_shutdown)
signal.signal(signal.SIGINT, graceful_shutdown)
```

**Ventaja**: Intenta cleanup ordenado pero garantiza terminación en tiempo acotado.[^4_9][^4_12][^4_8]

### 5. Integración con orquestadores (Kubernetes, SLURM, Airflow)

Para que el orquestador detecte fallos correctamente:

```python
# Exit codes estándar para orquestadores
EXIT_SUCCESS = 0
EXIT_ERROR = 1
EXIT_TIMEOUT = 124
EXIT_OOM = 137  # Kubernetes OOMKilled
EXIT_SIGNAL_BASE = 128  # 128 + signal_number

def fail_fast_oom():
    """Terminación por out-of-memory (GPU/CPU)"""
    os.write(2, b"FAIL_FAST: OOM detected\n")
    os._exit(EXIT_OOM)  # Kubernetes marca como OOMKilled

def fail_fast_timeout():
    """Terminación por timeout de operación"""
    os.write(2, b"FAIL_FAST: Operation timeout\n")
    os._exit(EXIT_TIMEOUT)  # Estándar en CI/CD
```

**Beneficio**: Los orquestadores pueden tomar acciones específicas (restart, escalar, alertar).[^4_9][^4_5]

## Tabla: `sys.exit()` vs `os._exit()` en pipelines distribuidos

| Característica | `sys.exit(code)` | `os._exit(code)` |
| :-- | :-- | :-- |
| Lanza `SystemExit` | ✅ Sí | ❌ No |
| Ejecuta `finally` | ✅ Sí | ❌ No |
| Ejecuta `atexit` handlers | ✅ Sí | ❌ No |
| Ejecuta `__del__` destructores | ✅ Sí | ❌ No |
| Ejecuta `sys.excepthook` | ✅ Sí | ❌ No |
| Flush automático de I/O | ✅ Sí | ❌ No |
| Riesgo de deadlock | ⚠️ Alto en GPU/IPC | ✅ Cero |
| Tiempo de terminación | Variable (ms-s) | Atómico (µs) |
| Código de retorno al SO | ✅ Sí (si no deadlock) | ✅ Sí (garantizado) |
| Uso recomendado | Scripts normales, CLI | Pipelines, GPU, IPC, signals |


______________________________________________________________________

## Cuándo NO usar `os._exit()`

`os._exit()` es **demasiado agresivo** para:

- **Scripts CLI normales** — usa `sys.exit()` para que `finally` y `atexit` limpien archivos temporales.[^4_4][^4_5]
- **Aplicaciones con estado persistente** — bases de datos, archivos abiertos que necesitan flush.[^4_2][^4_6]
- **Entornos donde el cleanup es seguro** — sin GPU, sin IPC, sin locks compartidos.[^4_10][^4_3]

**Regla empírica**: Si tu código toca **GPU, sockets IPC, shared memory, o signal handlers**, usa `os._exit()`.[^4_1][^4_7][^4_8]

## Módulo completo: `invariants.py`

```python
"""
invariants.py - Validación de invariantes inmune a python -O
Para FPU hardening, telemetría y signal handlers en producción.

Uso:
    from invariants import require, require_async_safe, InvariantError
    
    # Validación normal
    require(fpu_state.is_valid(), "FPU corrupto", fpu_state=fpu_state.dump())
    
    # En signal handlers (async-safe)
    require_async_safe(condition, "Violación en handler")
"""

import os
import sys
import logging
import signal
from datetime import datetime, timezone
from typing import Any, Callable, Type, Optional, Dict
from contextlib import contextmanager
from functools import wraps

# ============================================================================
# JERARQUÍA DE EXCEPCIONES
# ============================================================================

class InvariantError(RuntimeError):
    """Base para todas las violaciones de invariantes críticas."""
    def __init__(self, msg: str, **context: Any):
        super().__init__(msg)
        self.timestamp = datetime.now(timezone.utc).isoformat()
        self.context = context
    
    def __str__(self) -> str:
        return f"{self.__class__.__name__}: {super().__str__()} [t={self.timestamp}]"


class FPUInvariantError(InvariantError):
    """Violación de invariante en estado FPU (unidades de coma flotante)."""
    pass


class TelemetryInvariantError(InvariantError):
    """Violación en pipeline de telemetría o ingestión de datos."""
    pass


class SignalHandlerInvariantError(InvariantError):
    """Violación en contexto de signal handler - requiere cleanup inmediato."""
    pass


class ContractViolationError(InvariantError):
    """Violación de precondición o postcondición (Design by Contract)."""
    pass


# ============================================================================
# LOGGER DEDICADO
# ============================================================================

logger = logging.getLogger("invariants")
logger.setLevel(logging.ERROR)

# Handler por defecto (stderr) si no está configurado
if not logger.handlers:
    handler = logging.StreamHandler(sys.stderr)
    handler.setFormatter(logging.Formatter(
        "[INVARIANT] %(asctime)s %(levelname)s %(message)s",
        datefmt="%Y-%m-%dT%H:%M:%S%z"
    ))
    logger.addHandler(handler)


# ============================================================================
# FUNCIÓN PRINCIPAL: require()
# ============================================================================

def require(
    condition: bool,
    msg: str,
    exc_type: Type[InvariantError] = InvariantError,
    log_level: int = logging.ERROR,
    fatal: bool = False,
    **context: Any
) -> None:
    """
    Validación incondicional de invariantes - inmune a python -O.
    
    Args:
        condition: Invariante a verificar (debe ser True)
        msg: Mensaje descriptivo del error
        exc_type: Tipo de excepción a lanzar (para clasificación)
        log_level: Nivel de logging (ERROR, CRITICAL, etc.)
        fatal: Si True, termina el proceso después de loggear (para estados irrecoverables)
        **context: Datos adicionales para telemetría (ej: fpu_state, stack_trace)
    
    Raises:
        exc_type: Si condition es False
    
    Example:
        >>> require(x > 0, "x debe ser positivo", x=x)
        >>> require(fpu_state.valid(), "FPU corrupto", exc_type=FPUInvariantError, fpu_state=fpu_state.dump())
    """
    if not condition:
        # Enriquecer contexto automáticamente
        context["timestamp"] = datetime.now(timezone.utc).isoformat()
        context["exception_type"] = exc_type.__name__
        
        # Loggear antes de lanzar (para telemetría)
        log_record = {
            "message": msg,
            **context
        }
        logger.log(log_level, "Invariant violation: %s", log_record)
        
        # Lanzar excepción
        exc = exc_type(msg, **context)
        
        # Si es fatal, loggear stack trace y terminar
        if fatal:
            import traceback
            logger.critical("FATAL invariant violation - terminating process")
            logger.critical(traceback.format_exc())
            os._exit(1)
        
        raise exc


# ============================================================================
# VERSIÓN ASYNC-SAFE PARA SIGNAL HANDLERS
# ============================================================================

def require_async_safe(condition: bool, msg: str, exit_code: int = 1) -> None:
    """
    Validación mínima para signal handlers - solo operaciones async-signal-safe.
    
    Operaciones seguras: os.write(), os._exit()
    Operaciones NO seguras: logging, print(), raise, malloc, I/O complejo
    
    Args:
        condition: Invariante a verificar
        msg: Mensaje (se escribe directamente a stderr)
        exit_code: Código de salida si falla
    
    Warning:
        Esta función NO lanza excepciones - usa os._exit() directamente.
    """
    if not condition:
        # Async-safe: escribir directamente a stderr (fd=2)
        error_msg = f"\n[SIGNAL INVARIANT VIOLATION] {msg}\n".encode('utf-8')
        os.write(2, error_msg)  # fd 2 = stderr
        os._exit(exit_code)  # Async-safe exit (no cleanup)


# ============================================================================
# DESIGN BY CONTRACT: DECORADOR @contract
# ============================================================================

def contract(
    pre: Optional[list] = None,
    post: Optional[Callable[[Any], bool]] = None,
    exc_type: Type[ContractViolationError] = ContractViolationError
) -> Callable:
    """
    Decorador para Design by Contract - precondiciones y postcondiciones.
    
    Args:
        pre: Lista de tuplas (condition, msg) para precondiciones
        post: Función que recibe el resultado y devuelve bool (postcondición)
        exc_type: Tipo de excepción para violaciones
    
    Example:
        @contract(
            pre=[
                (lambda x: x > 0, "x debe ser positivo"),
                (lambda x: isinstance(x, (int, float)), "x debe ser numérico"),
            ],
            post=lambda result: result >= 0
        )
        def sqrt(x): ...
    """
    def decorator(func: Callable) -> Callable:
        @wraps(func)
        def wrapper(*args: Any, **kwargs: Any) -> Any:
            func_name = func.__name__
            
            # Verificar precondiciones
            if pre:
                for i, (condition, msg) in enumerate(pre):
                    # Si condition es callable, evaluarlo
                    cond_result = condition(*args, **kwargs) if callable(condition) else condition
                    require(
                        cond_result,
                        f"Precondition [{i}] failed in {func_name}: {msg}",
                        exc_type=exc_type,
                        function=func_name,
                        precondition_index=i
                    )
            
            # Ejecutar función
            result = func(*args, **kwargs)
            
            # Verificar postcondición
            if post is not None:
                post_result = post(result) if callable(post) else post
                require(
                    post_result,
                    f"Postcondition failed in {func_name}",
                    exc_type=exc_type,
                    function=func_name,
                    result_type=type(result).__name__
                )
            
            return result
        return wrapper
    return decorator


# ============================================================================
# CONTEXT MANAGER: INVARIANT TRANSACTION
# ============================================================================

@contextmanager
def invariant_transaction(
    msg: str,
    state_obj: Any,
    exc_type: Type[InvariantError] = InvariantError,
    rollback: bool = True
):
    """
    Context manager para invariantes transaccionales - verifica antes y después.
    
    Args:
        msg: Mensaje descriptivo
        state_obj: Objeto con métodos .is_valid(), .snapshot(), .restore()
        exc_type: Tipo de excepción
        rollback: Si True, restaura estado inicial si falla la invariante final
    
    Example:
        with invariant_transaction("Telemetry buffer", buffer):
            buffer.append(data)
    """
    # Capturar estado inicial
    initial_state = state_obj.snapshot() if hasattr(state_obj, 'snapshot') else None
    
    # Verificar invariante inicial
    require(
        state_obj.is_valid(),
        f"Initial invariant failed: {msg}",
        exc_type=exc_type,
        transaction=msg,
        phase="initial"
    )
    
    try:
        yield
        
        # Verificar invariante final
        require(
            state_obj.is_valid(),
            f"Final invariant failed: {msg}",
            exc_type=exc_type,
            transaction=msg,
            phase="final"
        )
        
    except Exception:
        # Rollback si está habilitado y hay snapshot
        if rollback and initial_state is not None and hasattr(state_obj, 'restore'):
            state_obj.restore(initial_state)
            logger.warning(f"Rolled back transaction: {msg}")
        raise


# ============================================================================
# VERSIÓN DEBUG-ONLY PARA CHECKS COSTOSOS
# ============================================================================

def require_debug(
    condition: bool,
    msg: str,
    exc_type: Type[InvariantError] = InvariantError
) -> None:
    """
    Check costoso que solo corre en debug/testing - se elimina con python -O.
    
    Usar solo para validaciones de desarrollo que no afectan correctness en producción.
    
    Example:
        >>> require_debug(verify_checksum(data), "Checksum inválido")  # Solo en debug
    """
    if __debug__ and not condition:
        raise exc_type(f"[DEBUG ONLY] {msg}")


# ============================================================================
# UTILS: VALIDADORES COMUNES PARA FPU Y TELEMETRÍA
# ============================================================================

def require_finite(value: float, msg: str = "Valor no finito", **context: Any) -> None:
    """Valida que un float sea finito (no NaN, no Inf)."""
    import math
    require(math.isfinite(value), msg, exc_type=FPUInvariantError, value=value, **context)


def require_bounds(
    value: float,
    lower: Optional[float] = None,
    upper: Optional[float] = None,
    msg: str = "Fuera de bounds",
    **context: Any
) -> None:
    """Valida que un valor esté dentro de límites opcionales."""
    if lower is not None:
        require(value >= lower, f"{msg}: {value} < {lower}", exc_type=FPUInvariantError, **context)
    if upper is not None:
        require(value <= upper, f"{msg}: {value} > {upper}", exc_type=FPUInvariantError, **context)


def require_schema(
    data: Dict[str, Any],
    required_fields: list,
    msg: str = "Schema inválido",
    **context: Any
) -> None:
    """Valida que un dict tenga los campos requeridos (para telemetría)."""
    missing = [f for f in required_fields if f not in data]
    require(
        len(missing) == 0,
        f"{msg}: campos faltantes {missing}",
        exc_type=TelemetryInvariantError,
        missing_fields=missing,
        **context
    )
```

### 1. FPU Hardening

```python
from invariants import require, require_finite, require_bounds, FPUInvariantError

class FPUState:
    def __init__(self):
        self.precision_mode = None
        self.rounding_mode = None
        self.masked_exceptions = set()
    
    def is_valid(self) -> bool:
        return (
            self.precision_mode in (32, 64, 80) and
            self.rounding_mode in ('nearest', 'down', 'up', 'truncate') and
            len(self.masked_exceptions) <= 5
        )
    
    def dump(self) -> dict:
        return {
            'precision': self.precision_mode,
            'rounding': self.rounding_mode,
            'masked': list(self.masked_exceptions)
        }

def fpu_compute_sqrt(x: float, fpu_state: FPUState) -> float:
    # Precondiciones
    require(fpu_state.is_valid(), "FPU en estado inválido", 
            exc_type=FPUInvariantError, fpu_state=fpu_state.dump())
    require_finite(x, "Input no finito", value=x)
    require_bounds(x, lower=0.0, msg="Raíz de negativo")
    
    import math
    result = math.sqrt(x)
    
    # Postcondición
    require_finite(result, "Resultado no finito", value=result)
    require(result >= 0.0, "Resultado negativo inesperado")
    
    return result
```

from invariants import require, require_schema, TelemetryInvariantError, invariant_transaction

class TelemetryBuffer:
    def __init__(self, max_size: int = 1000):
        self.data = []
        self.max_size = max_size
    
    def is_valid(self) -> bool:
        return len(self.data) <= self.max_size
    
    def snapshot(self) -> list:
        return self.data.copy()
    
    def restore(self, state: list) -> None:
